# Accumulated context

Use the user's existing structure where possible. If they ask to create one, offer these plain Markdown records; create only those with content:

| Record | Include | Keep elsewhere |
| --- | --- | --- |
| Context | Stable factual background, activities, ongoing learning | Current interpretations and emotional turning points |
| Goals | The user's own stated directions and requests | Goals inferred from the assistant's worldview |
| Motivations | Enduring things the person likes creating or contributing | Current tasks and temporary enthusiasm |
| Patterns | Repeated unwanted responses with episode references | Proposed solutions and one-off incidents |
| Strengths | Supported capacities and practical uses | Flattering identity claims |
| Practice chains | Understandings, choices, and corresponding actions with status | Claims that a new understanding is already habitual |
| Applications and results | Client-reported attempts and results, dated and quoted | Insight, intention, or agreement alone |
| Family facts | Reported relationships, events, dates, and source uncertainty | Automatically inferred inherited causes |
| Backlog | Unresolved interpretations and open questions | Unsupported certainty |

Each addition retains its session reference and date. Update an existing entry instead of duplicating it; preserve contradictory or corrected history with clear status. Separate `proposed`, `accepted`, `attempted`, and `reported result`. The label `verified result` requires appropriate independent evidence.

If compact summaries are requested for another tool, preserve the full record and produce a separate compact view within that tool's actual limit. A 980-character limit belongs to one original integration; it is not a universal requirement. No external synchronization is included here.
