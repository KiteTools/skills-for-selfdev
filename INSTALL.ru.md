# Установка Skills for Selfdev

[English](INSTALL.md) · **Русский** · [На главную](README.ru.md)

Начни с того результата, который нужен тебе сейчас. Три маршрута независимы: для ретро не нужен Telegram, а для ежедневного помощника не нужна история компьютера.

| Маршрут | Что ты получишь | Что потребуется |
| --- | --- | --- |
| [Практики по запросу](#on-demand) | Контекст помощника, ретро и другие выбранные скиллы в твоём AI-агенте | Git, Python 3.10+, агент и твои материалы |
| [Telegram-помощник](#telegram) | Личный текстовый диалог, журнал и сообщения по расписанию | macOS/Linux, Python, Node.js, OpenClaw, свой бот и постоянно работающая машина |
| [Источники активности](#activity) | Проверенная сводка дня для последующего разбора | Подготовленные записи или разрешённые экспорты; Python для локального расчёта |

**Агенту:** прочитай выбранный маршрут и `SKILL.md` компонента. Проверь среду, сохрани существующие настройки, используй только выбранные владельцем источники. Запиши SHA, версии, приватные пути и результаты проверки в частный `setup-report.md` без секретов. Различай установленные файлы и проверенную работающую интеграцию.

## Общий старт

В новой папке исходников:

```sh
git clone https://github.com/KiteTools/skills-for-selfdev.git
cd skills-for-selfdev
git rev-parse HEAD
python3 --version
python3 scripts/install.py --list
```

Если копия уже есть, сначала проверь её изменения и выбранную версию. Все команды ниже выполняй **из корня репозитория** в shell macOS/Linux. Примеры `/absolute/private/...` замени своими абсолютными путями. Контекст, журнал, токены, экспорты и отчёты храни вне публичной копии.

Коллекция — **0.3.3**; вложенная программа Telegram-помощника — **0.3.0**. Это разные версии. Текущие манифесты: [коллекция](plugin.json), [транспорт](skills/personal-daily-assistant/assets/runtime/openclaw-plugins/personal-daily-transport/package.json).

| Проверенная опора | Граница проверки |
| --- | --- |
| CI: Python 3.10 и 3.12, Node.js 22 на Linux | Проверяются пакет и тесты; живая доставка Telegram в CI не проверяется |
| Программа помощника рассчитана на macOS/Linux | Нативный Windows не поддерживается; WSL отдельно не проверен |
| Манифест транспорта объявляет OpenClaw `>=2026.7.1` | Это ограничение зависимости, не перечень проверенных релизов; свою версию проверь при подключении |

<a id="on-demand"></a>
## 1. Практики по запросу

Можно начать с одной практики, например `weekly-review`. Для личного контекста добавь `personal-codex-assistant`, для десяти возможностей дня — `evening-ten`. Название `personal-codex-assistant` историческое: [есть маршрут для Claude Code](docs/guides/daily-assistant-claude-code.ru.md).

**Codex:** копирование в пользовательский каталог `~/.agents/skills/`:

```sh
python3 scripts/install.py personal-codex-assistant weekly-review evening-ten
```

**Claude Code:** копирование в каталог скиллов выбранного приватного проекта:

```sh
python3 scripts/install.py personal-codex-assistant weekly-review evening-ten \
  --dest /absolute/private/assistant/.claude/skills
```

Выбери одну подходящую команду. Установщик копирует папки целиком и отказывается перезаписывать существующие. Он не создаёт личный контекст, `CLAUDE.md`, бота или расписание. Настроить контекст и сохранить прежние инструкции агенту помогает [готовый промпт для Claude Code](prompts/setup-daily-assistant.claude.ru.md). Для другого агента укажи его поддерживаемый каталог через `--dest` либо передай `SKILL.md` вместе со связанными файлами.

**Первый запуск:** открой сессию агента в выбранном проекте и попроси:

> Примени weekly-review к этим вымышленным заметкам за 15–21 апреля 2030 года, UTC: в понедельник я подготовил черновик; во вторник проверил его и исправил две ошибки. За остальные дни данных нет. Покажи, что подтверждено, и сохрани пробелы. Ничего не записывай и не планируй.

В Codex можно явно вызвать `$weekly-review`, в Claude Code — `/weekly-review`. Если скилл не обнаружен, начни новую сессию или перезапусти приложение и проверь каталог. **Готово**, когда агент прочитал установленный скилл, выполнил пробу и не выдал дни без записей за дни без деятельности. Эта проба проверяет доступность и базовое поведение, а не качество всех будущих ответов.

**Обновление и отключение:** просмотри изменения, сохрани прежнюю папку скилла вне каталогов обнаружения и установи выбранную версию заново. Свои блоки `CLAUDE.md`/`AGENTS.md` сопоставь отдельно, сохранив личные правила. Чтобы отключить скилл, убери его из каталога обнаружения; контекст и журнал сохраняй отдельно. [Другие требования по скиллам](docs/getting-started.ru.md).

<a id="telegram"></a>
## 2. Telegram-помощник

Здесь устанавливается отдельная программа OpenClaw. Копирования скилла в агента недостаточно. Нужны свой бот, числовой Telegram ID владельца, приватный файл токена, часовой пояс IANA и постоянно доступный компьютер. Команды и диалоги программы преимущественно на русском. OpenClaw и его модель настраиваются отдельно; подписка на AI-приложение сама по себе не подключает модель к OpenClaw.

### Подготовь свою конфигурацию

Прочитай [SKILL.md](skills/personal-daily-assistant/SKILL.md) и [контракт установки](skills/personal-daily-assistant/references/installation-contract.md). Проверь `python3 --version`, `node --version`, `openclaw --version` и `openclaw --help`.

Проверь поставляемые компоненты на вымышленных данных, без живой отправки:

```sh
python3 -m unittest discover -s skills/personal-daily-assistant/tests
python3 -m unittest discover -s skills/personal-daily-assistant/assets/runtime/tests
node --test skills/personal-daily-assistant/assets/runtime/openclaw-plugins/personal-daily-transport/test/*.test.mjs
```

Сохрани копию [шаблона контекста](skills/personal-daily-assistant/assets/templates/active_context.json) в приватном `context.json`. Замени все `REPLACE_WITH_YOUR_`, срок фокуса и пример задачи своими значениями. Не заполняй их придуманными ответами ради проверки: если пока не хочешь задавать контекст, начни с маршрута 1.

Подготовь эти значения в своей shell-сессии. Все пути — примеры; папка `assistant` должна **ещё не существовать**, даже пустой. Папка данных находится отдельно от неё. Файл токена уже должен существовать и принадлежать тебе; его содержимое не передавай в чат или аргументы команды.

```sh
SELFDEV_PRIVATE="/absolute/private/selfdev"
SELFDEV_OWNER_ID="YOUR_NUMERIC_TELEGRAM_ID"
SELFDEV_TIMEZONE="Europe/Paris"
SELFDEV_OPENCLAW_CONFIG="/absolute/private/openclaw/openclaw.json"
SELFDEV_OPENCLAW_SESSIONS="/absolute/private/openclaw/sessions"
SELFDEV_TOKEN_FILE="/absolute/private/secrets/telegram-token"
SELFDEV_PYTHON="$(python3 -c 'import sys; print(sys.executable)')"
SELFDEV_SETUP_AT="$(date -u +%Y-%m-%dT%H:%M:%SZ)"
chmod 600 "$SELFDEV_TOKEN_FILE"
```

### Проверь план, затем установи файлы

```sh
python3 skills/personal-daily-assistant/scripts/install.py \
  --project-root "$SELFDEV_PRIVATE/assistant" \
  --data-dir "$SELFDEV_PRIVATE/data" \
  --context-json "$SELFDEV_PRIVATE/context.json" \
  --summaries-dir "$SELFDEV_PRIVATE/summaries" \
  --timezone "$SELFDEV_TIMEZONE" \
  --owner-telegram-id "$SELFDEV_OWNER_ID" \
  --telegram-target "$SELFDEV_OWNER_ID" \
  --openclaw-config "$SELFDEV_OPENCLAW_CONFIG" \
  --openclaw-sessions-dir "$SELFDEV_OPENCLAW_SESSIONS" \
  --token-file "$SELFDEV_TOKEN_FILE" \
  --python-bin "$SELFDEV_PYTHON" \
  --thread-cleanup-cutoff "$SELFDEV_SETUP_AT"
```

Без `--apply` команда проверяет входные данные и выводит JSON с `mode: dry-run`; папки установки не создаёт. Просмотри пути, владельца, часовой пояс и **7 деклараций расписания**: 03:00, 08:00, 12:00, 15:10, 18:00, 22:00 и воскресенье 20:00. Техническая очистка выключена; параметр cutoff сам её не включает.

Если план подходит, повтори эту же команду, добавив `--apply`. Ожидаемый результат — `mode: applied-local-files`, приватный журнал и файлы `assistant/setup/openclaw-plugin-fragment.json`, `assistant/setup/schedule-declarations.json`. OpenClaw и задания ещё не подключены.

### Подключи и проверь доставку

Сделай резервную копию действующей конфигурации OpenClaw рядом с оригиналом. Проверяющий скрипт ищет имя `<имя-конфига>.backup-<дата>`:

```sh
cp -p -n "$SELFDEV_OPENCLAW_CONFIG" "$SELFDEV_OPENCLAW_CONFIG.backup-$SELFDEV_SETUP_AT"
```

По интерфейсу своей установленной версии подключи плагин из `assistant/openclaw-plugins/personal-daily-transport`, перенеси его настройки из фрагмента и настрой ссылку на файл токена. `telegram_guardrails` во фрагменте описывает требования установки; не вставляй его как неизвестный ключ в живую конфигурацию. Ограничь бота владельцем, отключи группы для этого бота, сохрани Gateway на loopback и не меняй доступ других ботов. Если их нельзя изолировать, выбери отдельный экземпляр OpenClaw.

Зарегистрируй выбранные задания по одному разу, сохранив `declaration_key`, часовой пояс, `cwd`, `argv` и переменные окружения. Не запускай одновременно старую и новую установку на одном журнале. Универсальная команда регистрации здесь намеренно не приведена: схема CLI зависит от релиза OpenClaw.

```sh
python3 skills/personal-daily-assistant/scripts/verify.py \
  --project-root "$SELFDEV_PRIVATE/assistant" \
  --data-dir "$SELFDEV_PRIVATE/data" \
  --token-file "$SELFDEV_TOKEN_FILE" \
  --openclaw-config "$SELFDEV_OPENCLAW_CONFIG"
```

Проверка должна вернуть `ok: true`; поле `runtime_verified` остаётся `false`. Она проверяет файлы и поддерживаемую часть строгого JSON, но не работающий процесс. JSON5/includes проверь средствами своего OpenClaw. Затем проверь загрузку плагина, действующие ограничения доступа, единственность расписаний и один текстовый диалог с владельцем: ответ пришёл, соответствующее событие появилось в журнале ровно один раз. Только после этого помощник **работает и проверен**.

«Десятка» необязательна. Флаг `--enable-evening-ten` при подготовке создаёт **8 деклараций**: доставка подборки в 22:00, ретро в 22:10. Он не добавляет сборщик или генератор. Сначала настрой [подготовку, проверку и импорт подборки](skills/personal-daily-assistant/references/evening-ten-integration.md).

**Обновление и отключение:** используй [обновление в соседнюю папку](skills/personal-daily-assistant/references/installation-contract.md#supported-hosts-and-safe-upgrade). Останови старые задания и процессы записи, сделай backup контекста, приватных данных и конфигурации, затем переключай пути. Для отключения останови задания и входящий транспорт этой установки, выключи её плагин; журнал сохрани. Откат требует сначала остановить новую установку, затем вернуть прежние пути и задания. Автоматического переключения или отката нет.

<a id="activity"></a>
## 3. Источники активности

Начни с собственных заметок: они уже подходят для вечернего и недельного разбора. История устройств нужна только если ты хочешь дополнить картину. Этот маршрут обрабатывает выбранные данные; он не устанавливает наблюдение за компьютером.

| Источник | Что есть в поставке | Что подключается отдельно |
| --- | --- | --- |
| Твои заметки и результаты | Практики ретро и явные записи в журнале помощника | Выбор материала |
| Данные устройств и самоотчёты | CLI `cross-device-day-review` для нормализованного JSON | Экспорт из выбранного сервиса и проверка преобразования |
| Машинное время Codex/Cursor | Правила ретро, расчёт завершённых интервалов в CLI | Сборщик метаданных; сборщика Cursor, hooks и чтения его базы здесь нет |
| Выбранные экспорты переписки Codex | Отдельный необязательный механизм вечернего помощника | Подготовленные приватные экспорты; механизм читает текст сообщений, не только длительности |

### Запусти вымышленный пример

```sh
SELFDEV_DEMO="$(mktemp -d)"
python3 skills/cross-device-day-review/scripts/day_review.py \
  --config skills/cross-device-day-review/examples/config.json \
  --input skills/cross-device-day-review/examples/day.json \
  --output-dir "$SELFDEV_DEMO/report"
```

Результат — `report.md`, `report.json`, `compact.json` в новой папке. В примере человеческие интервалы дают **140 минут**, машинный runtime — **90 минут**, объединённый машинный интервал — **60 минут**. Планшет остаётся отсутствующим источником, а разговор без длительности — неизвестным временем. Отчёт `partial` допустим: это неполные свидетельства, а не ошибка. Пример вымышленный; доступа к твоей истории нет.

### Подготовь свои данные

По [контракту входа](skills/cross-device-day-review/references/input.md) создай приватные `config.json` и `day.json`, затем повтори команду с их путями и новой папкой результата. CLI принимает нормализованный JSON, а не произвольный экспорт ActivityWatch, RescueTime или другого сервиса. [Границы адаптеров](skills/cross-device-day-review/references/adapters.md) объясняют, что можно извлечь и что останется неизвестным. Не превращай приблизительные длительности в выдуманные точные интервалы.

Для машинных запусков нужны проверенные начало, конец и устойчивый обезличенный ID. Сохрани раздельные источники Codex/Cursor, исключи дубли и дочерние запуски из суммы корневых. CLI считает общий runtime и объединённый интервал; его минуты по источникам — **объединённые интервалы, не runtime каждого провайдера**. [Правила ретро](docs/guides/agent-time-retrospectives.ru.md) описывают эту разницу и покрытие по дням. Отчёты стороннего сборщика требуют проверки определения времени, часового пояса и формата перед включением.

Передай проверенную сводку агенту с просьбой применить `weekly-review` или `evening-ten`. Автоматического импорта этих файлов в Telegram-программу нет.

Для отдельного чтения выбранных экспортов переписки Codex вечерним помощником следуй [контракту подключения](skills/personal-daily-assistant/references/installation-contract.md#optional-activity-data): нужны обе переменные `PDS_INCLUDE_CODEX_ACTIVITY=1` и абсолютный `PDS_CODEX_ACTIVITY_SOURCE_DIR`. Не указывай всю живую историю по умолчанию. Этот механизм извлекает фрагменты сообщений; результат может попасть в Telegram и контекст модели. Даже транспортный dry-run читает данные при включённой опции.

**Готово**, когда источник и период известны, преобразование проверено, сводка сохраняет пропуски, а повторные записи не увеличивают время. **Отключение:** перестань передавать источник; для Codex-интеграции убери включающий флаг или установи `0`. Внешние сборщики отключаются отдельно по их инструкции. Обновление скилла само их не меняет.

## Где проверить результат

[GitHub Actions](https://github.com/KiteTools/skills-for-selfdev/actions) показывает проверки конкретного коммита. [Описание проверок](docs/validation.ru.md) сохраняет историю прежних выпусков; оно не заменяет проверку твоей установки. Начальная проверка файлов:

```sh
python3 scripts/check_repo.py
```

В своём `setup-report.md` отдели **работает и проверено**, **подготовлено, но требует живой проверки**, **не подключено по твоему выбору**. Сохрани там способ отключения и обновления выбранного маршрута. [Приватность](PRIVACY.ru.md) · [Карта системы](docs/system-map.ru.md) · [Каталог](docs/catalog.ru.md).
