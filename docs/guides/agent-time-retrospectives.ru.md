# Cursor и Codex в вечернем и недельном ретро

[English](agent-time-retrospectives.md) · **Русский**

**Увидеть, что ты сделал сам, что поручил агентам и какой результат успел проверить.** Время работы Cursor помогает дополнить картину дня, но не заменяет рассказ о твоём опыте. Вечерний разбор сохраняет это различие; недельный показывает его вместе с пробелами за каждый день.

## Какие данные передать

Достаточно твоих записей и выбранных результатов. Если хочешь учитывать машинное время, дополнительно передай проверенную сводку с датой, часовым поясом, длительностью Codex и Cursor и охватом каждого источника. При наличии отдельных запусков нужны только обезличенные идентификаторы, начало, конец, признак корневого запуска и подтверждение завершения. Содержимое запросов, ответов и результатов инструментов для подсчёта не требуется.

Псевдонимы и метки времени тоже могут быть чувствительными: храни исходные сводки в приватной папке. Не загружай в публичный Git базу Cursor, личные названия проектов, переписку, ключи или пути к домашней папке.

## Как читать машинное время

| Показатель | Что означает |
| --- | --- |
| Твоё время | Подтверждённые или явно описанные тобой занятия, с учётом пересечений |
| Runtime Codex / Cursor | Сумма длительностей завершённых корневых запусков соответствующего агента; параллельные запуски могут пересекаться |
| Объединённый интервал машинной работы | Сколько времени по часам покрывают известные интервалы хотя бы одного запуска; это не сумма параллельных запусков |
| Известный машинный итог | Сумма доступных runtime по агентам, с явной отметкой неполноты |
| Результат и понимание | Проверенные файлы, тесты, наблюдаемый результат и твой рассказ; из времени работы агента они не следуют |

В runtime входят инструменты и ожидания внутри запуска. Это не GPU-время, стоимость и не часы твоей работы. Активное окно Cursor тоже не доказывает, что агент в это время выполнял запрос.

Для Cursor предпочтительны сопоставленные события начала запроса и завершения. Резервная сводка метаданных от запроса до финального сообщения даёт частичную оценку. `turnDurationMs` может описывать лишь последний рабочий отрезок: нельзя подставлять его вместо всей длительности или использовать возраст чата. Незавершённый запуск без конечной отметки остаётся без длительности.

Один запуск из hooks и резервных метаданных учитывается один раз. Дочерний агент не прибавляется к родительскому запуску. Отсутствующий источник — **н/д**, а не ноль. Успешная проверка CLI не доказывает, что hooks редактора присылают события; Tab, облачные агенты и CLI без подтверждённого сбора остаются за пределами этой сводки.

## Вечером

Сначала собери занятия и проверенные результаты, затем покажи машинное время отдельной строкой. Уточни только существенные пропуски. Не превращай большой runtime в успех, малый — в провал, а недоступность Cursor — в отсутствие работы. «Десятка» может использовать проверенный результат для предложения, но не делает вывод о твоём развитии по машинным минутам.

## За неделю

Проверь каждую дату в твоём часовом поясе, даже если вечернего отчёта за неё нет. Если ты разрешил отдельный сборщик и он доступен, обнови сводки закрытых дней. Если нет — используй предоставленные данные и покажи их охват.

Свежая сводка **заменяет значение этого агента за соответствующий день**. После этого общий итог пересчитывается из значений Codex и Cursor. Прибавлять Cursor к итогу, который уже содержит Cursor, нельзя. Человеческие интервалы при таком дополнении не переписываются. Для старых экспортов `agent_time_context` схем 1–3 поле `agent_runtime_min` означало только Codex; для других форматов сначала нужно выяснить контракт.

Покажи для каждого агента дни с числовыми наблюдениями, неполные дни и даты без данных. Даже корректный ноль в выбранном экспорте не доказывает, что весь день наблюдался. Не восстанавливай недельное время умножением среднего на пропущенные дни.

## Вымышленный пример

Это специально придуманные данные, без личного дневника. Неделя — 15–21 апреля 2030 года, UTC.

- 15 апреля: Codex 09:00–09:30; Cursor 09:10–09:30. Повтор этой же записи Cursor в другом источнике исключён. Дочерний запуск 09:15–09:20 не прибавлен. Охват Cursor частичный.
- Твой отдельный самоотчёт: проверка результата 09:20–09:35 — 15 минут. Эти минуты не получают прибавку за работу агентов.
- 16 апреля: Codex — 20 минут завершённого запуска; Cursor — н/д.
- За остальные пять дней сводок нет.

Вечером 15 апреля: **машинный runtime — известные 50 минут: Codex 30, Cursor ≥20; объединённый интервал — 30 минут**. Известная проверка человеком — отдельно 15 минут.

За неделю: **известный машинный итог ≥70 минут: Codex 50 минут, данные за 2/7 дней; Cursor ≥20 минут, данные за 1/7 дней, этот день неполный**. Это не всё время недели и не оценка твоего понимания. Если более свежая сводка Cursor за 15 апреля уточнит его runtime до 25 минут, итог станет 75, а не 95.

## Запрос агенту

> Разбери эти записи дня или недели с учётом предоставленной сводки Codex и Cursor. Отдели моё время, машинное время, проверенный результат и понимание. Учти дубли, частичное покрытие и свежие поправки. Покажи дни без данных; не читай историю редактора и не устанавливай сборщики без отдельного запроса.

## Что поставляется

В коллекции 0.3.3 обновлены инструкции недельного ретро, оператора ежедневного помощника и контекста «Десятки». **Сборщик Cursor, чтение его SQLite-базы, установка hooks и автоматический импорт машинных сводок в Telegram не входят в этот выпуск.** Существующая интеграция экспорта переписки Codex — другой механизм: она читает текст и не является сбором одних метаданных.

Обновление GitHub не меняет уже установленного помощника. Для существующей установки сначала сопоставь новые правила с её приватным `AGENTS.md`, сохрани личные настройки и перенеси только согласованные дополнения. Расписания и работающий OpenClaw от обновления инструкций не меняются.
